# PetLink 功能原型 V1.3 — Frozen

本轮继续依据已 Frozen 的 M01～M08、UC-01～UC-07 与 REST API 补齐原型表达，不新增业务模块。

## 已修正

1. M01 / M07 四个死按钮
   - 取消收藏：移除收藏卡片 + Toast
   - 保存资料：Toast 后回个人中心
   - 登录：切到 USER + Toast + 首页
   - 创建账号：Toast + 登录页

2. 审核驳回原因校验
   - 线索驳回：空白原因阻止操作
   - 领养拒绝：空白原因阻止操作

3. M02 待审核线索图片编辑
   - 已有图片缩略图
   - 添加图片
   - 删除图片
   - 最后一张禁止删除
   - 最多 9 张

4. M05 领养申请详情
   - 领养理由
   - 住房条件
   - 家庭成员
   - 养宠经验
   - 联系方式

5. M06 回访非空校验
   - content / healthCondition / 有效图片至少一项
   - 全空时显示 40001

6. M08 时间范围趋势
   - from / to 日期范围
   - 本月快捷选择
   - 应用范围后更新趋势标题与示意图
   - 刷新反馈

7. 文件限制 UI
   - JPG / JPEG / PNG
   - 单张 ≤ 5MB
   - 线索 / 回访单次最多 9 张
   - UC-04 SUCCESS 所有 Animal 图片合计最多 9 张
   - Animal 图片单次新增最多 9 张
   - 格式/大小错误 Toast 演示

## 同时补强

- VISITOR 演示状态：公开动物、动物详情、公告可访问；受保护功能自动引导登录。
- 重复领养申请：提交后再次申请示意 `40907 ADOPTION_APPLICATION_ALREADY_EXISTS`。
- 收藏：首次收藏变为“已收藏”，展示幂等语义。

## 不纳入 HTML 的实现细节

JWT/RBAC 内部链路、TemporaryFile token、条件更新与行锁、幂等缓存/指纹、OperationLog、文件补偿清理等继续由 API、序列图、数据库和测试表达。

## 文档冲突提醒

旧 `project_state.md` 中若仍写“仅 USER 可以申请领养”，必须在需求追踪矩阵前统一为：

`USER / RESCUER 均可申请领养；ADMIN 独立审核。`

需求基线文件需要在制作需求追踪矩阵前单独完成同步，本目录仅归档已冻结的交互功能原型。
