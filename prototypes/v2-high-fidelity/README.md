# PetLink 高保真原型 V2.1

本目录以功能原型 V1.3 Frozen 为业务基线，只重构视觉系统、信息层级、响应式表现和演示交互，不改变 M01～M08、UC-01～UC-07、角色权限与状态规则。

## 视觉方向

**城市动物救助档案 × 温暖领养社区**

- 行动色：救援橙 `#E85F3E`
- 工作台深色：森林墨绿 `#173D39`
- 健康色：草木绿 `#6F8F6B`
- 纸张底色：`#F3F0E8`
- 辅助色：珊瑚棕 `#C97B5D`、雾蓝绿 `#8EB6B0`
- 标题使用带人文感的衬线字体；正文使用清晰的系统无衬线字体；状态、编号和英文眉题使用等宽字体。

移动端以动物照片和“动物档案卡”为第一视觉层级；详情页把状态章、健康摘要与救助时间线组合成可辨识的 PetLink 档案语言。RESCUER 页面改为面向行动的任务面板。PC 端则采用“救助中心工作台”，优先展示紧急线索和待处理任务，数据统计退到第二层级。

## 文件

- `pc-admin-prototype.html`：PC 救助中心工作台高保真原型
- `mobile-user-prototype.html`：移动端领养社区与救助行动原型
- `assets/`：原型使用的本地动物影像与生成说明

两个 HTML 均可直接离线打开；为了避免浏览器限制本地资源，推荐在本目录启动静态 HTTP 服务后预览。正式编码阶段应将视觉 Token、组件状态和响应式规则迁移到 Vue 3、Element Plus 与 UniApp，不把这些单文件 HTML 直接当作生产代码。

## V2.1 功能收口

- 公开首页只展示 `AVAILABLE` 动物；治疗或观察中的动物不进入公开领养列表；
- `AVAILABLE → SUSPENDED` 在 PC 和移动端均要求填写非空暂停原因；
- 负责动物管理、领养概览与历史回访通过选中对象上下文动态渲染，不再串用固定动物或固定回访；
- 动物详情的基本信息、健康记录、救助来源，以及救助任务的待处理、进行中、已完成均可真实切换；
- 两端演示城市统一为上海。
- `Animal #5001` 在所有页面统一为“布丁 / AVAILABLE”；申请 `#6001` 为其待审核申请，不生成领养事实记录；
- 历史 `AdoptionRecord #7001` 与回访记录改用已领养动物“豆包 #4991”，与待领养的布丁保持独立；
- 工作台不使用 Frozen 模型以外的优先级和排期字段，所有状态章与时间标签均来自 `status`、发现时间、接取时间、开始时间或完成时间；
- 布丁救助时间线统一为 08-13 发现和救助、08-14 体检、08-16 建档。

## 保留的功能

- PC 端 9 个管理页面、弹窗、审核校验、状态动作和统计时间范围；
- 移动端 29 个页面、USER / RESCUER / VISITOR 权限边界；
- 线索图片 1～9 张约束、回访非空校验、重复申请和收藏幂等演示；
- 所有原有按钮、`data-goto` 跳转和 JavaScript 业务演示逻辑。

## 可访问性与动效

- 为按钮、输入框和选择器提供键盘焦点样式；
- 页面切换自动回到顶部，避免二级页面从中部开始展示；
- 页面与弹窗仅使用一次性的短过渡；
- 遵循 `prefers-reduced-motion`，用户要求减少动态效果时关闭动画。
