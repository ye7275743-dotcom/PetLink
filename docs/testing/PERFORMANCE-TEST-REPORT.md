# PetLink V1.0 性能测试报告

执行日期：2026-09-02  
环境：本机 Spring Boot + JDK 17 + Docker MySQL 8.0.46  
原始证据：`docs/testing/evidence/performance-2026-09-02.json`

## 1. 验收指标

依据详细设计 NFR：

- 并发用户数：50。
- 普通查询 P95 ≤ 2 秒。
- 普通新增/修改 P95 ≤ 3 秒，不含图片网络上传时间。
- 本次验收追加要求：HTTP 及业务 API 成功率 100%。

## 2. 方法

- 预先注册并登录 50 个隔离 USER 账号；注册、BCrypt 和登录耗时不计入测量。
- 每个工作线程对应一个真实登录用户，使用屏障同时释放 50 个线程。
- 每种场景每用户执行 3 次，共 150 个样本。
- 查询场景交替访问 `GET /api/animals?page=1&size=20` 和 `GET /api/announcements?page=1&size=20`。
- 修改场景访问 `PATCH /api/users/me`，每个用户只修改自己的昵称，避免业务资源锁互相干扰。
- 使用真实本地 MySQL，不使用 Mock 数据库；原始证据不保存 token 或密码。

## 3. 结果

| 场景 | 并发用户 | 样本 | 成功率 | 平均 | P50 | P95 | P99 | 最大 | 门槛 | 结果 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---|
| 普通查询 | 50 | 150 | 100% | 28.842 ms | 27.071 ms | **52.696 ms** | 75.361 ms | 97.856 ms | P95 ≤ 2000 ms | 通过 |
| 普通修改 | 50 | 150 | 100% | 45.206 ms | 39.945 ms | **83.827 ms** | 110.017 ms | 115.527 ms | P95 ≤ 3000 ms | 通过 |

## 4. 判定

- 并发用户数满足 50 用户要求。
- 查询 P95 仅占门槛的约 2.63%。
- 修改 P95 仅占门槛的约 2.79%。
- 300 个计时请求全部获得 HTTP 2xx 且业务 `code=0`。

V1.0 必要性能验收：**通过**。

## 5. 适用边界

本结果证明当前开发机、单实例和本地数据库条件下满足详细设计门槛，不等同于公网、弱网或生产多节点容量结论。图片上传、长时间稳态压测、数据库大数据量、管理列表图片 N+1 和跨地域延迟未纳入本轮必要验收，建议在正式部署环境另做容量测试。

## 6. 复现命令

后端和 MySQL 启动后，在 `server/` 执行：

```bash
python3 scripts/performance_m01_m08.py
```

脚本在任一成功率或 P95 门槛不满足时返回非零退出码。
